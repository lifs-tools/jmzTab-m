# 1.0.7-SNAPSHOT to 1.0.8-SNAPSHOT behaviour comparison

## What was compared

- Baseline: commit `53242461` (1.0.7-SNAPSHOT, the build the validator uses today).
- New line: `release/1.0.8` at `cf49da16` (1.0.8-SNAPSHOT). Range `53242461..cf49da16`:
  - `4c3e8079` report all missing abundance columns in SMH/SFH headers, assays first
    (from master `910bc44b`),
  - `3cef606f` CLI fails on unreadable JSON (from master `b7c36c3f`; CLI only, does not
    touch `MzTabFileParser`),
  - `cf49da16` version bump to 1.0.8-SNAPSHOT.
- Method: both builds (`./mvnw -B -q package -DskipTests -DskipITs`, no `install`) run
  `new MzTabFileParser(file).parse(OutputStream.nullOutputStream(), MZTabErrorType.Level.Info, 10000)`
  over every file; each build uses only its own jmztabm jars (cli jar plus `cli/target/lib`).
  One line per message (file id, level, code, line, whitespace-normalised message text),
  sorted so message order does not count, then `diff`ed. A message text change on an
  otherwise equal line would therefore also show up.

## Result

- Fixtures: the sorted outputs are byte-identical. No per-code count differs, 0 files affected.
- Corpus: the sorted outputs are byte-identical. No per-code count differs, 0 files affected.
- Every difference is therefore explained (there are none): no regression, and no change
  caused by anything other than the two ported fixes.

The corpus and the fixtures contain no file whose header lacks abundance columns, so the
fix is not exercised by them. To show that the comparison can see the fix, three derived
files (a public fixture, `metabolomics/official-profile-ms.mztab`, with abundance columns
removed from SMH and SML) were run through both builds:

| Derived file | 1.0.7-SNAPSHOT | 1.0.8-SNAPSHOT |
|---|---|---|
| all `abundance_*` columns removed | `IOException` (validation stopped at the first missing column) | 365 x Error-2009 (`NotDefineInHeader`) on the SMH line, one per missing column |
| two assay abundance columns removed | 2 x Info-2057 | identical |
| one assay and one study variable column removed | 2 x Info-2057 | identical |

This is the intended effect of `4c3e8079`: all missing abundance columns are reported
(extra Error-2009 on SMH/SFH lines, and validation that used to stop at the first one now
continues). The derived files are not committed; the comparison scripts are kept outside
the repository and can be rerun after the backport.
